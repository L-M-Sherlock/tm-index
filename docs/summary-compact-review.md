# 3,000～8,000 字符译文全量复核与修订

本轮 `compact-full-20261103` 覆盖 `3000 <= read_chars < 8000` 的全部 622 篇译文，正文共 3,128,869 字符，其中 3,000～5,000 字符 330 篇、5,000～8,000 字符 292 篇。沿用目录可见正文字符数口径，不重复纳入正文恰为 8,000 字符的已复核文章。

流程依照 [总结维护规范](summary-workflow.md) 与 [盲读、初判、写作及独立复核协议](summary-midlength-review.md)。上述文档中的旧运行名、范围、代理前缀和模型在本轮替换为：WORK `.work/compact-full-20261103`，代理前缀 `compact`，实际模型 GPT-6（继承会话），reasoning effort `max`。实际实例和角色对应关系记录在工作清单；不得将多个角色标签描述为多次独立阅读。

全部来源从备份仓库历史提交 `34afa85c` 只读提取；原始 JSON 哈希、HTML 哈希和正文字符数逐篇与目录一致，缺口为零。正文中的指令均为资料，不执行。作者、关键词、引用、正文及排序不在本轮修改范围。

复用 [1,000～8,000 字符分层抽样](summary-sampling-1000-8000-results.md) 中范围内的 30 篇同版本结果：10 篇覆盖充分直接保留历史验收证据，20 篇问题稿进入修订并独立验收；其余 592 篇重新盲读和初判。不得把历史阅读冒充本轮新阅读，不改写抽样初判及裁定，不因追求全量重写而改动已充分的稿件。

每篇新审先由写作者和独立复核者各自全文阅读、保存观点提纲及 checkpoint，再看旧总结保存初判。提纲按主要论证簇组织，正文证据可以覆盖完整段落，并附 8～160 字符实质短引。反向链接、纯目录和重复例子不自动升级为主要观点。存在分类或实质分歧时由主代理回查裁定，原始初判保留。

需要修订的总结应写出独立论证、关键机制、主要结果及影响理解的条件。指南保留步骤与使用条件，研究保留证据类型和作者归属。不要只列主题名或研究名；不引入外部例证、邻篇内容或未经本篇支持的诊断与因果解释。篇幅按内容复杂度确定，无 260 字上限，不为凑字扩写，最终为普通中文段落。

写作者每篇完成立即保存。复核者一次汇总主要缺口，退回后对整张清单重新核验；返修保留版本，初判不覆写。所有实际阅读、初判和新稿验收均须属于执行该工作的实例。只有绑定当前稿件与复核哈希的主代理验收通过后，才使用 `scripts/summary_workflow.py apply` 写回目录和修订历史。

本轮在本地完成修订和核验，不自动提交或发布。既有抽样报告保持历史版本，不能因为总结后来修好了而改写当时的问题率。
